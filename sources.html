### 1.2 Активы — форма 0409101

- ✅ Каталог пакетов: `https://cbr.ru/banking_sector/otchetnost-kreditnykh-organizaciy/` (ссылки с 2004 г.).
- URL-паттерн: `https://cbr.ru/vfs/credit/forms/101-YYYYMM01.rar` — **RAR v5** (распаковывать `bsdtar`, macOS ок). Ежемесячно; последний на дату разведки — `101-20260701.rar` (данные на 01.07.2026, опубликован ~24.07 → лаг ~3.5 недели).
- Внутри DBF, **кодировка cp866**, суммы в тыс. руб.:
  - `MMYYYYB1.dbf` — остатки: `REGN, PLAN` (глава А/Б/В/Г + ITGAP-итоги), `NUM_SC` (счёт), `A_P`, `VITG` (вход. остаток), `OITGA/OITGP` (обороты), `IITG` (исход. остаток), `DT`.
  - `MMYYYYN1.dbf` — 354 банка: `REGN, NAME_B`.
  - `NAMES.dbf` — справочник счетов.
- Структура пакета (выяснено на Этапе 2): счета первого порядка (3 знака) + сгруппированные строки с точкой (`45.0`, `60.0`…) + строка-итог `ITGAP`; вместе (без ITGAP) они образуют полное разбиение валюты баланса.

**Методика активов (зафиксирована на Этапе 2, согласована с заказчиком 27.07.2026):**

Активы = **оценка нетто-активов** из главы А публикуемого пакета 101-й формы:
сумма активных остатков МИНУС активные стороны парных/технических счетов
(303 внутрибанковские, 706/707/708 доходы-расходы, 610/612 выбытие, 105/106
контр-капитальные) МИНУС контрарные пассивные остатки на счетах активной
природы (резервы, амортизация, переоценка: 203, 320–325, 441–473 и группы
44.x–47.x включая 474 с резервами 47425, 501–519, 604/607/608/609/619/620/621).
Полный список префиксов — `_EXCLUDE_ACTIVE` / `_CONTRA_PASSIVE` в `app/pipeline/cbr.py`.

⚠️ Это **оценка**: точное официальное «Всего активов» (ф. 0409806) из
публикуемого пакета невоспроизводимо — ЦБ сводит баланс по счетам второго
порядка, а пакет агрегирован до первого. Калибровка против ф.806 на 01.04.2026:
Сбербанк +0.26%, ВТБ −0.67%, Райффайзенбанк −0.77%, Совкомбанк −1.48%;
у платёжных НКО ошибка может достигать десятков процентов (внутренние
взаимозачёты второго порядка) — РНКО «Платёжный Центр» +31%. В UI цифры
активов помечаются как оценка; эталон для квартальной сверки — ф.806
(`cbr.ru/banking_sector/credit/coinfo/f806/?regnum={N}&dt={YYYY-MM-DD}`).

Перекрёстная проверка (Этап 2): единого определения «нетто-активов» не
существует — на 01.04.2026 по Сбербанку: наша оценка 65.31 трлн ₽,
официальная ф.806 65.14 трлн, «агрегированный баланс» по алгоритму ЦБ для
30 крупнейших (analizbankov.ru) 67.93 трлн, методика banki.ru (пары
«актив−пассив» с floor 0 по PDF-методике 01.2024) — ещё один вариант.
Наша оценка калибруется на официальную ф.806 — это осознанный выбор эталона.
kuap.ru мёртв (домен захвачен спам-сайтом, страницы 404) — не использовать.

Пробел SWIFT: у нескольких банков (Совкомбанк, РФК-банк) нет SWIFT в ЕД807;
ИНН теперь есть у всех из карточек finorg.
Не раскрываются 18+ мес (активы/капитал = прочерк): БЭНК ОФ ЧАЙНА (2309),
АйСиБиСи Банк (3475), МОСОБЛБАНК (1751) и ещё 3–4 КО — это норма, не ошибка.

### 1.3 Капитал — форма 0409123

- URL-паттерн: `https://cbr.ru/vfs/credit/forms/123-YYYYMM01.rar` (RAR v5, ежемесячно; последний — `123-20260701.rar`, данные на 01.07.2026).
- Внутри DBF cp866: `*_123D.dbf` — данные `REGN, C1` (код строки), `C3` (тыс. руб.); `*_123N.dbf` — справочник строк; `*_123B.dbf` — реквизиты банков.
- **Итог капитала — строка `C1='000'`** («Собственные средства (капитал), итого»). Пример: REGN=1 (ЮниКредит) → 369 763 728 тыс. руб.

### 1.4 Курсы валют

- ✅ `https://cbr.ru/scripts/XML_daily.asp[?date_req=DD/MM/YYYY]` — XML windows-1251.
- USD: `ID=R01235`, Nominal=1. JPY: `ID=R01820`, **Nominal=100** (курс за 100 иен — брать `VunitRate` или Value/Nominal).
- ⚠️ Десятичный разделитель — запятая. Если на дату курса нет, возвращается ближайший предыдущий — читать атрибут `Date` из ответа, не предполагать.

### 2.2 Структура и идентификаторы (классический формат)

`<sdnEntry>`: `uid`, `lastName` (название), `sdnType=Entity`, `programList`
(`RUSSIA-EO14024`, `UKRAINE-EO13662`, …), `idList` — там всё нужное:

- ОГРН → `idType="Registration Number"`, ИНН → `"Tax ID No."`, **BIC → `"SWIFT/BIC"`**, LEI → `"Legal Entity Number"`.
- Директивы — псевдо-id: `"Executive Order 13662 Directive Determination -"` → `"Subject to Directive 1"`; `"Listing Date (EO 14024 Directive 3):"` и т.п.
- Образец: `docs/samples/ofac_sdn_sberbank.xml` (Сбербанк, uid 17018: SDN + SSI одновременно).

### 2.3 Типы (SDN / SSI / CAPTA) и даты включения

- Классический Consolidated **не содержит** явного поля типа списка. Надёжное различение — advanced-формат: `SanctionsEntry@ListID`: `1550`=SDN, `91507`=SSI, `91763`=CAPTA, `92052`=Non-SDN CMIC; `SanctionsTypeID`: 91505–91514 = 13662 Directives 1–4, 92087/92093 = EO 14024 Directive 3/2.
- **Designation dates — только в advanced**: `SanctionsEntry → EntryEvent(EntryEventTypeID=1) → Date` (+ `LegalBasisID` → справочник EO). У одного банка несколько дат — по одной на каждый список (Сбербанк: SDN 06.04.2022, SSI 12.09.2014).
- ⚠️ Один банк может быть и в SDN, и в SSI (одинаковый uid/ProfileID в обоих файлах) — тип привязывать к списку-источнику, дедупликация по uid.
- В advanced есть кириллические названия (ScriptID=220) — полезно для матчинга.

### 2.4 Триггер обновлений

- **Лучший**: ✅ `https://sanctionslistservice.ofac.treas.gov/changes/latest` — дельта-XML (`<entity action="add|modify|delete">`, `datePublished`). Образец: `docs/samples/ofac_changes_latest.xml`.
- ✅ `https://ofac.treasury.gov/recent-actions` — HTML (Drupal), блоки `.views-row`, ссылки `/recent-actions/YYYYMMDD[_NN]`; RSS-фида у раздела нет (❌ `/recent-actions/feed` — 404).

## 3. EU — FSF + EUR-Lex

### 3.1 Consolidated Financial Sanctions File (FSF)

**EU Login / персональный токен НЕ нужен.** Официальный публичный RSS
✅ `https://webgate.ec.europa.eu/fsd/fsf/public/rss` (без авторизации) публикует
прямые ссылки с общим токеном `dG9rZW4tMjAxNw`:

- ✅ XML 1.1: `https://webgate.ec.europa.eu/fsd/fsf/public/files/xmlFullSanctionsList_1_1/content?token=dG9rZW4tMjAxNw` (~25 МБ, 6017 записей; также CSV/XSD/PDF/XML 1.0).
- ⚠️ Токен общий и теоретически может ротироваться — **на каждом прогоне брать актуальные ссылки из RSS**, токен не хардкодить. Переменная `EU_FSF_TOKEN` остаётся как опциональный override.
- ⚠️ Без токена: `.../content` → 403, кривой токен → 500, PDF без токена → **200 с пустым телом** — мониторить по контенту, не по коду ответа.
- В RSS у item есть `pubDate` и `guid` с SHA1-чексуммой файла — готовый детектор изменений.

Структура XML (`xmlns=http://eu.europa.ec/fpi/fsd/export`): `sanctionEntity
@euReferenceNumber @designationDate` → `regulation @numberTitle @publicationDate
@programme` (+`publicationUrl` на EUR-Lex), `subjectType@code=enterprise`,
`nameAlias@wholeName`, `identification@identificationTypeCode`:
**`swiftbic`, `regnumber`, `taxid`** и др. Программа России — `UKR` (регламент
269/2014), 2745 записей. Образец: `docs/samples/eu_fsf_sberbank.xml`.

- Типы мер — два представления: строка `SanctionsImposed` (токены через `|`, регистр непоследователен) и **`SanctionsImposedIndicators` — 15 boolean-элементов (надёжнее)**: `AssetFreeze`, `TrustServicesSanctions`, `DirectorDisqualificationSanction`… ⚠️ Часть мер (Correspondent banking) есть только в строке — парсить оба.

- ⚠️ Идентификаторы: SWIFT/BIC у российских банков отсутствует; ИНН/ОГРН — грязный свободный текст в `BusinessRegistrationNumber` (у Sberbank — голый ОГРН; **у VTB и Gazprombank отсутствуют вовсе**) → матчинг по названиям + NonLatinNames.
- Триггер: ✅ gov.uk Content API `https://www.gov.uk/api/content/government/publications/the-uk-sanctions-list` — JSON с `public_updated_at` и полным `change_history` (457 записей) + актуальными URL вложений. Дешёвая проверка — HEAD на XML (`ETag`). ❌ Atom-фида нет.

## 6a. Ловушки матчинга (выявлены на Этапе 3)

1. **Дубли в XML_bic.asp**: у одного БИК бывают две записи с разными ИНН
   (у БИК ЮниКредита вторая запись содержит ИНН Росгосстраха) — берём первую.
2. **Иностранные дочки в OFAC**: украинские Sberbank/VTB (BIC SABRUAUK/VTBRUAUK)
   матчились по имени → для матчей по имени введён гейт по стране адреса записи
   (нужна Russia); id-матчи не ограничиваются.
3. **JP-список использует переводы, а не транслитерацию** (Credit Bank of
   Moscow = МКБ) и бренды (Bank Rossiya) → ручные матчи в overrides.
4. **Переименования**: Промсвязьбанк → «Банк ПСБ», Тинькофф → «ТБанк» —
   старые названия в списках, новые в реестре → overrides.
5. **Похожие имена ≠ тот же банк**: СГБ(Севергазбанк)≠Сургутнефтегазбанк,
   ТКПБ(Тамбов)≠Транскапиталбанк, БМВ Банк≠БМ-Банк, ВБ Банк≠VTB,
   МБ Банк(Иран)≠MRB(Цхинвал) — в exclusions.json с пояснениями.
6. Не действующие КО (Открытие, Росбанк, РНКБ, СМП — присоединены; ВЭБ.РФ —
   не КО) корректно остаются несматченными — это не пропуск.
7. **Слияния и переименования (требование заказчика, реализовать на Этапе 5):**
   санкционные списки продолжают нести старые названия/ИНН после слияний.
   Дифф обязан различать причины изменения матчей: (а) запись удалена из
   списка → алерт «снятие санкций»; (б) запись на месте, но банк исчез из
   реестра действующих (отзыв/реорганизация) → алерт модератору «проверьте
   правопреемника, возможен override» (+статус из карточки finorg);
   (в) смена названия при том же ОГРН (Тинькофф→ТБанк) → алерт модератору.
   Санкции автоматически НЕ переносятся на правопреемника — только через
   overrides решением модератора.
